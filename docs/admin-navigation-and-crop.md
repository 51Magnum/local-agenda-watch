# Admin navigation and manual image cropping

Every admin page now shares a private layout with current-page highlighting, breadcrumbs, a page introduction and a route back to the overview. The phone menu collapses behind **Admin menu**. Sections are **Content & Review**, **Images**, **Jurisdictions**, **Residents & Plans**, **Alerts & Emails**, **Corrections**, and **Privacy & Audits**. The overview has one card per section, with pending evidence, queued jurisdiction exceptions, flagged/withheld image and pending correction counts. Missing storage produces “count unavailable”, never a guessed zero.

Existing page actions, authorization, delivery gates, classifiers, source collectors and production budgets remain in place. Buttons receive a visible one-sentence explanation and a confirmation before changes. Evidence keyboard actions also confirm. Resident plan changes keep their existing server-stored two-step confirmation. The standalone confirmation document uses the same menu configuration and explicit return links. Read-only searches, filters, previews and navigation do not ask for a mutation confirmation.

Dead ends addressed: all existing admin pages are in the menu; case-image breadcrumbs return through the area-filtered image inventory rather than a nonexistent `/admin/images/<area>` page; staged-project breadcrumbs return to the jurisdiction section rather than a nonexistent area index; content backfill displays its existing JSON result inside the admin page; account confirmation has menu/breadcrumb links; storage failures have an admin error screen with a return link. The existing health information remains below the overview cards.

On an image card, **Crop** opens the full stored source page. Only accepted, current, privacy-approved source pages are eligible. Generated GIS fallback images need no document crop and cannot be cropped through this editor. Drag with a pointer/touch, or enter the crop in original page pixels. The server validates integer bounds and a minimum 16×16 region, uses the existing sharp pipeline, and sends the exact new preview bytes through the existing personal-information classifier under its global and jurisdiction budgets. Development tests mock the classifier; no paid model is called during validation.

Passing manual crops get a new immutable visual asset, retain the full original page, and store the pixel box, source asset/page hashes, preview hash, admin actor and time in the existing image record JSON. The card says **Manually cropped**. Selection and hidden flags remain intact, and automatic collection cannot overwrite a manual crop. **Reset to auto crop** recomputes the automatic crop from the preserved original and checks that new preview again. No DB migration or environment variable is needed.

A failed or unavailable check keeps the previous image. Changed sources or concurrent review changes refuse the save. Public preview responses require the source-page approval, active catalog entry and matching pixel hashes, plus a passing crop-specific approval for manually reviewed previews. Protected residential cases, stale source checks and revoked sources stay withheld. The preview caption follows its own classification, so a cropped vicinity inset is labelled as context rather than a proposed layout. Official source URLs and physical PDF-page provenance remain unchanged.

All pages retain the existing admin protection and no-cache/noindex behavior. Preview keeps its existing read-only evidence-review exception; other private admin pages and all writes remain blocked there. No production data is read or changed by the local browser fixture, which uses an in-memory database and mocked classification.
