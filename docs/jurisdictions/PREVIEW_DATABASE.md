Preview mutations and cron routes return HTTP 403 whenever `VERCEL_ENV` is not `production`. Direct onboarding, map and privacy writes also refuse. All runtime Postgres pools use read-only sessions outside production; runtime schema initialization is skipped. Existing production initialization and normal approved email delivery are unchanged. Onboarding schema is migration-owned.

Set `DATABASE_URL_PREVIEW` in Vercel **Preview** to a separate Neon branch or a read-only role provisioned by the owner. Example format only: `postgresql://preview_reader:REDACTED@preview.example.invalid/law?sslmode=require`. Never commit a connection string. If it is absent, preview reads can use the inherited `DATABASE_URL`, but the application forces a read-only Postgres session. A distinct Neon branch/read-only role is still recommended as an independent protection. Provision its schema with the repository migrations before using the app; previews never create tables.

Preview watch signup writes are the sole exception: they require an explicitly separate `DATABASE_URL_PREVIEW` value and remain tagged `preview:<branch>`. The preview alert pool can write only to that configured database; no preview email delivery is enabled. Without an isolated DSN, preview signup storage refuses writes. Separate-value checks do not prove two URLs identify different databases: the owner must verify the Neon branch/role and privileges.

Before accepting a preview, inspect the Neon connection's branch and role in Vercel settings without exposing credentials. Run the preview mutation tests, check an authorized preview cron request returns 403, and verify no Neon production writes occurred. Do not execute staging backfills against production from a preview or override the runtime environment to make a preview writable. No isolated Neon branch has been provisioned or verified by this code change.
