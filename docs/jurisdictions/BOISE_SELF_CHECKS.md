# Boise source-aware self-checks

The initial production run collected 302 records, but none could publish. The privacy gate assumed every feed supplied an applicant column, nineteen official descriptions were null, Accela's valid search-to-case redirects were rejected, and source verification restarted after each 180-second budget.

The generic ArcGIS adapter now supports an explicit public-column projection. Boise excludes `RecordName` and other identity/contact columns at collection; unknown/private columns are discarded and unsafe projection configurations fail. Resident text, types, statuses and URL values still undergo privacy checks. Null descriptions pass only when LAW displays no description.

Boise's configured same-origin Accela redirect must point to the official case-detail route with all required case components and the Boise agency code. The actual 302 is retained as redirect evidence, never relabeled HTTP 200. It is accepted only with an independently fetched restricted query returning exactly one matching RecordID and only permitted public fields. Foreign/login redirects, missing identifiers and mismatched data fail.

Core application and agenda links are verified first. HTML identity hashes bind the case IDs used by the check instead of rotating form tokens; PDF hashes and exact-record response hashes remain intact. Private evidence checkpoints are scoped to the exact staged snapshot, collection timestamp and configuration and expire after two hours. Successful evidence, real access blocks and unreadable-file outcomes are retained so later bounded passes continue unfinished work without repeatedly probing blocked files. The automatic migration has a down file; no new environment variables, roles, secrets or services.

The explicit `verified-only` document policy publishes only independently verified attachment links. Optional inaccessible, unreadable or wrong-case files are withheld from both the review snapshot and production projection, with a resident notice and private document exceptions. Core application/agenda identity must still pass; an attachment policy cannot approve a bad case. Verified files retain their actual document hashes. Optional availability does not redefine the project identity; the complete source inventory remains bound by the snapshot hash. Other jurisdictions retain their existing document policy.

Read-only official-source result: 302 records; 301 eligible (99.67%); all three coverage checks pass. PLN25-00608 remains withheld for its boundary exception. The committed review records 52 definite document exceptions and 25 records with optional document verification still pending; those links are absent from resident data. They require no per-project approval. Further bounded passes can verify additional files without changing the core project decision.

The snapshot scan found zero emails and zero matches for candidate individual identities from the original source-name field. The built Preview renders Boise with no database and shows real source-based titles and missing-document notices on desktop and mobile. No screenshots, production shell writes or paid AI in development.

Validation: 972 tests pass in 184 files; typecheck and standard/zero-DB Preview builds pass; lint has zero errors and four existing warnings. Three browser checks pass at desktop and phone sizes. Four offline executions of the actual workflow verify resumed collection, deferred verification, bounded optional-document retries and immediate stop on access-blocked collection sources. The 95% minimum and material project-source drift threshold are unchanged.
