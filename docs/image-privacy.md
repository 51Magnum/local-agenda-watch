# Document image privacy gate

Emergency commit d114b3e withdrew all document images before re-enabling any previews. Unverified API assets return 410 and legacy optimized-image URLs remain blocked in the proxy. Document pages and source social images are replaced with the safe generic area social card.

Only the checked publication catalog can supply popup/project images. Legacy snapshots and hand-authored static image configuration cannot bypass it. Every candidate must have a plan/exhibit title or an explicitly titled plan/exhibit page within a report, and the entire rendered source page must pass low-detail vision with an allowed type, no personal information, and confidence >= 0.8. Both accepted and rejected results are cached by policy version and SHA-256 of the page pixels in Neon. Atomic reservation prevents parallel duplicate classification. Errors/crashed reservations are withheld, never treated as passes. No classification occurs on public page views.

Sign-in sheets, neighborhood meeting documents, letters, comments, notices, affidavits, mailing lists and application forms are rejected before model input. The vision prompt also rejects handwriting/signatures, photos of paper, narrative staff pages and any resident personal information. Unknown dates are omitted; captions use the classified type and an explicitly published source date.

Accepted full-page WebP assets bind their byte hash to the classifier result. The image endpoint checks both this binding and an active, non-hidden catalog record on every request. It returns private/no-store images; approved displays bypass the persistent Next image optimizer. The same gallery and popup viewer enlarge checked images without returning to unchecked original crops. Hide actions create source/case tombstones so refresh cannot silently re-publish the image.

Protected review: /admin/images, with per-case views at /admin/images/{area}/{caseId}. Review lists only already-checked images; rejected/withdrawn entries have metadata only. POST /admin/images/action requires the existing admin Basic authentication plus same origin. Actions: purge removes unverified cached/generated crops, audit inventories all configured areas and checks a bounded batch (resuming remaining entries), hide withdraws a catalog image and revalidates pages. Audit status distinguishes rejected, blocked and deferred; none publishes. Originals remain city records; the site does not cache/re-publish forbidden pages as images.
